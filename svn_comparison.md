# Сравнение Git и SVN

## 1. Почему в Git ветвление "дешёвое", а в SVN — "дорогое"?

Git — распределённая система контроля версий. Ветка в Git — это просто указатель на коммит (небольшой файл размером несколько десятков байт). Создание ветки происходит мгновенно, потому что не требует копирования файлов проекта — все коммиты уже есть локально.

SVN — централизованная система. Ветка в SVN — это копирование директории на сервере. При создании ветки SVN физически копирует все файлы проекта в новую директорию на сервере, что медленно и затратно по месту.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?

Нет, нельзя. SVN — централизованная система, у неё один общий сервер, где хранится вся история. Коммит в SVN — это отправка изменений на сервер. Без соединения с сервером коммит невозможен.

В Git коммит делается локально — вся история хранится на компьютере разработчика. Связь с сервером нужна только для push (отправки) и pull (получения). Поэтому в Git можно коммитить офлайн, а потом запушить, когда появится интернет.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?

- Legacy-проекты: если команда много лет работает на SVN, миграция на Git может быть дороже, чем продолжать на SVN.
- Строгий централизованный контроль: в некоторых госструктурах и банках требуется, чтобы вся история хранилась только на защищённом сервере, без локальных копий.
- Большие бинарные файлы: SVN умеет хранить их без раздувания репозитория (хотя сейчас есть Git LFS).
- Низкий порог входа: SVN проще для новичков, так как меньше команд и концепций (нет локальных коммитов, staging area и т.д.).
